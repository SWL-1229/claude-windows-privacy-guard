# 已有 Claude 安全环境的实时面板

适用于“想看当前优化后的 Claude 运行时是否正常、哪些保护在工作”的请求。目标是既有环境的实时可视化，不是另建一套网络保护或反复手动运行通用泄露检测。

## 发现与启动

1. 发现实际保护目录、当前 Claude 包、现有安全快捷方式与运行进程。默认目录只是 `%USERPROFILE%\.claude-network-guard`，非固定安装承诺。不要使用作者 IP 或复制他人的运行登记。
2. 查明 `detector/` 是否存在于当前 Skill/仓库；读 [命令说明](../detector/README.md)。Python/Tkinter 与原保护后端均须实际可用。没有后端时说明缺项，不生成空壳“安全”入口、不伪造登记。
3. 从当前 Skill 根运行 `pythonw -B detector/app.py --root '<本机已部署的绝对目录>'`。需要桌面入口时用 `detector/install_shortcut.py --guard-root '<实际目录>'`；它只创建面板快捷方式，已有同名链接须先核对并保留。
4. 用户从原有安全入口启动桌面或专用网页后，面板自动识别。面板不会启动 Claude 或保护服务、切换节点、变更系统时区、清理登录或放行流量；查看状态本身不授权这些操作。

## 读结果与排查

- **出口与许可：** 来自原网关当前验证和允许名单，不是普通浏览器的 IP 查询。入口跟随器报告最终出口不是固定家宽时，显示具体原因；这与“已检测到泄露”不同。不得为了变绿删除维护锁或切到直连。
- **时区/语言：** 桌面依赖原有实时页面监控的有效证明，网页区分启动实测与当前原生进程策略。不要用面板自身的时区/语言替代应用。
- **WebRTC：** 当前原生路由策略通过与重新采集 ICE 候选是两件事；面板不抢占 DevTools、不执行 STUN。未另做页面枚举时不能报告“私网地址彻底不暴露”。
- **DNS：** 专用 DNS 服务与有效 NRPT 是定向路由证据，不是权威解析日志的泄露实测。
- **UDP/IPv6：** 无权限读取实时 WFP 时明确待核验，旧安装报告不能替代内核与目标进程正反对照。
- **未运行 / 待验证：** 已确认没有对应进程才算未运行；权限、路径、证据时效问题算待验证。普通入口启动但缺少安全登记的 Claude 不能显示成已保护。

修复用户报告的保护故障时，继续按 [出口保护](exit-protection.md) 和 [启动维护](startup-prevention.md) 处理，不把查看面板扩大成清理登录或取消限制。

## 验收与交接

确认面板持续自动更新、切换分类与查看详情可用，状态不会用刷新时间冒充原证据时间；导出默认隐藏 IP、不含凭据或本地账号数据。关闭面板不影响原保护是重要边界，不能拿“关闭面板后 Claude 继续联网”误判为失败关闭失效。

报告分别列出：面板程序测试、当前真实运行观察、尚未做的泄露实测。需要进一步安全验收时读 [验收清单](acceptance.md)，不要仅因面板为绿色宣称全链路已通过。

## 管理员只读核验

新版面板的【管理员核验】仅重新打开只读观察器；Windows UAC 由用户确认。核对当前包对应读取器、清单和 SHA256，再逐条比较四类 WFP 规则的身份、层、动作、地址、端口和协议条件；只数规则条数不能判定通过。读取器准备见 [面板说明](../detector/README.md)，缺少绑定时保持待验证。Edge／Brave 的 IPv4 TCP、QUIC 与 WebRTC 行属于进程策略，不等同于桌面 WFP 或包级拦截实测。
