# 启动与更新后的预防检查

用于排查 Claude 桌面应用的 `ERR_PROXY_CONNECTION_FAILED`，以及预防应用更新、普通入口和 Electron 旧进程复用造成的代理配置失效。维护联网保护不需要清理登录信息；不要因此退出账号或删除数据。

## 已验证的故障机制

1. **入口使用了不同的代理。** 普通应用入口可能继承 Windows 系统代理；已有的进程级保护却只允许专用本地网关。此时出现代理连接失败，可能是保护正确拦截了错误路径，不能仅凭报错认定住宅代理不可用。
2. **应用更新后，登记仍指向旧包。** 更新可能改变软件包身份、安装路径和附带的可执行文件。仍引用旧路径或固定组件清单的规则需要重新审查；安全入口应在登记不一致时拒绝继续启动。
3. **新窗口仍复用旧主进程。** Electron 应用可能复用已经运行的主进程，新启动命令的代理参数未必生效。关闭窗口不一定退出后台进程，再点一次安全快捷方式也未必修正原进程。

这些是可复现的原因，不代表每一次代理连接失败都来自同一问题。

## 每次启动或更新后的流程

### 1. 发现当前安装与专用网关

- 使用 `Get-AppxPackage -Name Claude` 查询实际包身份和安装位置；不要从历史报告或 WindowsApps 目录通配结果猜测当前版本。
- 从用户现有的保护配置确定专用网关端口，并区分共享代理、专用网关和内部核心端口。不要把其他电脑的端口、出口名单或路径直接套用。
- 检查该端口是否监听，以及监听者是否是预期的本机进程。端口能连接仅证明存在服务，不能证明服务身份、上游可用或出口被允许。

### 2. 运行只读预检

在本技能目录运行，替换尖括号中的值：

```powershell
python scripts/launch_preflight.py --gateway-port <专用端口>
```

如果已有与当前保护安装对应的本机登记文件，可额外传入：

```powershell
python scripts/launch_preflight.py --gateway-port <专用端口> --installed-marker <本机登记文件>
```

该登记文件必须使用本工具明确支持的格式：

```json
{
  "schema_version": 1,
  "package_full_name": "<当前受保护软件包的完整名称>",
  "gateway_port": 12345
}
```

其中端口仅为格式示例，必须替换。登记是预期配置的记录，不是防火墙已安装或已生效的证据；不要为消除报错而把旧登记中的包名手动改成新版名称。旧工具生成的不同格式应先检查与转换，不能默认为可信。

预检应核对当前包、专用监听，以及可读取的 Claude 主进程代理参数；传入登记时再核对包身份和端口是否一致。代理参数应指向同一专用回环网关，并按当前保护设计核对绕过规则、QUIC 设置和冲突参数。子进程与主进程分开判断，不把 Electron 的正常辅助进程误当成启动入口。

### 3. 排除旧进程复用

如果发现没有专用代理参数、参数冲突、重复参数或无法核实的主进程：

1. 先保存 Claude 中的未提交内容和正在处理的工作。
2. 使用 Claude 菜单完整退出，再确认主进程已结束；关闭窗口或最小化不算完成退出。
3. 重新运行只读预检。
4. 在现有联网保护已独立验证后，从自己已经配置好的安全入口启动。

不要通过重复点击快捷方式、强制结束未保存工作、放开任意代理或关闭保护来解决。此技能附带的预检不会代替用户启动应用。

### 4. 发现包变化时重新验证覆盖

保持现有保护，暂停依赖该保护的操作。由现有保护工具重新发现当前包及相关组件，审查精确路径、目录边界、有效签名与发布者；根据实际组件生成计划，不能固定旧版本的组件数量或规则数量。

正式维护前保存工作并正常退出应用。若维护器会强制终止进程，先明确其行为与范围。维护应只改自身规则，保留用户主动设置的离线锁定，失败时回滚；探测完成后再次核对包身份与文件摘要，避免更新期间登记了旧路径。全部验证通过后才能更新登记。

本发布包不包含 WFP 安装器；上面描述的是现有保护方案必须满足的维护要求，不是本技能已经自动执行的动作。

## 独立验证：预检通过以后仍要做什么

按本次修改的范围，用无账号请求、隔离测试进程或独立浏览器配置验证。不得为了测试自动登录或发送用户消息。

| 检查 | 必须证明的结果 |
|---|---|
| 实际公网出口 | 从受保护专用通道发起新请求，当前出口在用户允许名单内 |
| 目标应用的实际连接 | 从目标进程、包身份或有效规则核对其仅使用被允许的网关；另一个测试程序成功不能代替目标应用验证 |
| 错误路径 | 目标身份尝试直连、共享代理和内部核心端口时均按设计被拒绝 |
| 失败关闭 | 住宅链路失效、出口不在名单或临时锁定时拒绝新转发，并按保护设计撤销已有转发 |
| 普通网络 | 受保护链路锁定时，无关网站仍遵循用户原有代理策略 |
| 启动后的应用 | 完整退出后从安全入口重新打开，实际页面可连接；同时再次检查当前主进程参数 |

临时测试前记录原状态，结束后恢复并复查。保留用户原有锁定，不遗留自己新建的锁定；不要拿旧 `status.json`、历史成功报告或一次端口连接结果代替当前验证。

## 停止条件与能力边界

- 预检为只读诊断：不修改系统或浏览器代理，不安装或刷新 WFP，不启动/关闭应用，不清理登录数据，也不提供持续监控或强制断网。
- 未传登记时，不能宣称已核对“当前包与已部署保护版本一致”；传了登记也只能证明记录一致，仍需独立验证实际规则。
- 端口监听、正确命令行参数和页面成功打开，都不足以单独证明固定出口或失败关闭。没有安装并验证进程级限制时，不得描述为“非指定 IP 自动断网”。
- 查询失败、权限不足、软件包无法唯一确定、未知登记格式、版本不一致、参数冲突或监听异常，应停止依赖该项保证的操作并报告原因。不要更改登记、删除防火墙规则、清空代理或改走任意节点来让检查变绿。
- 独立 Claude Code、外部 MCP、浏览器及虚拟机有各自的身份与网络路径；不能由桌面应用的检查推断其也受到保护。
- 此流程处理本地连接可靠性与隐私保护，不保证账号不被限制，也不改变服务端记录或设备硬件特征。
