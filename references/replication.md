# 在另一台电脑复现

此文给执行 Skill 的代理使用。先完成可用组件盘点，再实施用户选择的部分。仓库中的两个清理/预检工具和布局盘点工具可以直接运行；指定出口网关、WFP 安装器、DNS 服务、浏览器控制器及 DevTools 自动化后端**未随仓库分发**。没有这些组件时，只能完成对应的清理或只读检查，不能生成一个空壳“安全联网”快捷方式后报告部署成功。

## 1. 确认任务与参数

优先使用已连接设备、本次盘点和已有配置，缺失时再询问。记录在本地新报告中，不提交公开仓库。

| 需要确认 | 如何取得 |
| --- | --- |
| 清理范围 | 桌面、哪些浏览器配置；是否保留当前登录；默认保留 MCP、Code/Cowork 工作与其他站点 |
| 实际安装与资料目录 | `layout_inventory.py`；不固定用户目录、版本或组件数量 |
| 允许的公网出口 | 用户指定的自有出口；不是节点名称、入口 IP 或测速 IP |
| 住宅出口连接信息 | 本地配置中读取 SOCKS5/HTTP 类型、地址、端口及凭据，不输出凭据 |
| 入口节点 | 手动选择组；可切换入口，始终使用同一住宅出口；避免 DIRECT 回退和选择循环 |
| 本地专用端口 | 发现已有服务及监听者；无默认端口，不占用其他软件端口 |
| 时区和语言 | 独立选择；不要因清理登录而修改整机时区或语言 |
| 验证期限 | 按用户对安全与抖动的取舍设定；不是照抄作者的 4 秒或其他人的数值 |
| 已有实现 | 工具来源、源代码、签名/摘要、安装/卸载方式、规则覆盖和验收工具 |

缺少网络后端时，向用户明确说明缺少什么。若用户另行要求开发后端，应作为实际工程任务实现和测试，不能把本文件当作已经提供的安装器。不要从作者电脑复制运行目录、私密配置或二进制。

## 2. 先盘点实际布局

在 Skill 根目录运行：

```powershell
python -X utf8 scripts/layout_inventory.py
```

它可在 Claude 运行时检查当前包和进程暴露的资料目录，不输出完整启动参数。新版可能使用 `Claude-Data\claude_pzs8sxrjxfjjc`；只检查旧 MSIX `LocalCache` 可能得到“零 Cookie”，实际却仍登录。`review_needed`、未知/自定义目录或未识别安装必须先核对，不能自动扩大删除范围。

## 3. 按授权清理并独立复查

保存工作，菜单完整退出 Claude。仅关闭窗口可能驻留后台。先运行只读 `desktop_cleanup.py`；检查列出的所有实际根，再用 `--all-discovered --apply` 或单个精确 `--root` 清理。详见 [桌面清理](desktop-cleanup.md)。

多目录模式先对全部已选根预检，再逐根执行；它不是文件系统事务。某个文件被锁、磁盘失败或程序重新启动时，报告可能部分完成，应依据本轮报告补查，不能宣称全清。

浏览器按 [浏览器清理](browser-cleanup.md) 另行执行。遇到加密恢复备份或不能按站点拆分的共享缓存，保留并说明；只有明确获得扩大范围的授权后才处理。不要把“不清密码和书签”误说成“不会影响其他站点窗口恢复”。

## 4. 部署或维护真实保护后端

已有合适实现时按 [出口保护](exit-protection.md)、[更新与启动](startup-prevention.md) 核对后再使用。需要实现的关键性质：

1. 固定住宅出口，入口可更新；探测必须走受保护数据使用的同一条专用链路。
2. 强制进程边界：当前包及实际 EXE 只允许专用网关；阻止其他代理端口、直连、UDP、IPv6 绕行。版本变化重新登记，禁止只改 marker。
3. 新连接及已有转发都受有效许可约束；实际 IP 不符立即撤销许可。超时、迟到探测、旧缓存不能复活许可。
4. 出口验证与页面环境检测分开。页面刷新、目标切换不应被误判为上游 IP 更换；检测失效时按设计暂停传输，正常复验后恢复。不要用关闭浏览器替代每一次短暂线路波动。
5. 若多个探测源并发，必须使用可信、严格解析的实际 IP 结果；矛盾结果、重放或超时不能因“任一成功”而放行。控制并发，拒绝旧 generation 结果，不通过放宽有效期掩盖故障。
6. 控制器停止时保持拒绝；自己的维护锁绑定所有者及本轮身份，不能删除用户或其他维护任务的锁。普通站点路由单独验证。

代理启动参数本身不是防直连规则；系统代理/TUN 开启也不是防泄露证明。只修改 Clash 的 IPv6 开关不能代替进程级拦截，避免为了保护 Claude 关闭整台电脑无关网络。

## 5. 页面环境与 DevTools

DevTools 是 Electron/Chromium 自带工具；项目作者实现的是使用它的检测/启动流程。`Enable Main Process Debugger` 的 Node Inspector 与页面 DevTools 是不同接口，前者可能临时监听本机端口，维护结束应核对关闭，不能暴露到局域网。

- **时区：** 页面 `Intl`/`Date` 覆盖不证明 Windows 原生 API、独立 Code/MCP 或云端 Cowork 相同。费城使用 `America/New_York`（Windows 对应 `Eastern Standard Time`），夏令时随规则变化。整机修改需要明确授权；不同时修改时钟时间或强制语言。
- **语言：** 浏览器首选语言、页面 `navigator.language`、界面语言、系统首选语言可能不同。只实施用户要求的范围，不能因为界面显示英语就报告所有组件一致。
- **WebRTC：** 不以命令行开关或一个 mDNS 候选判定通过。实际检查 ICE 事件、SDP 和 stats 中的候选；当前主页面、刷新后和新 WebContents 分开测试。`disable_non_proxied_udp` 是路由策略，不等于关闭 WebRTC 或保证不枚举地址。涉及麦克风/摄像头停用时先确认功能取舍。
- **DNS：** 网页检测结果需要与本机实际解析路径相符；代理远端解析不代表全部 OS DNS 都已覆盖。只设置用户要求的范围，核对 IPv4/IPv6、直连失败路径与 DNS 服务退出情况。
- **工具依赖：** 若当前后端依赖附着 DevTools、可见窗口或前台输入，应公开说明。不要承诺可关闭/最小化或无人值守，除非该实现已实际通过测试；不能绕过 UAC、自粘贴保护或系统窗口输入保护。

权威接口：[Electron webContents / DevTools](https://www.electronjs.org/docs/latest/api/web-contents#contentsopendevtoolsoptions)、[WebRTC IP handling](https://www.electronjs.org/docs/latest/api/web-contents#contentssetwebrtciphandlingpolicypolicy)、[Microsoft WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/windows-filtering-platform-start-page)。文档接口存在不等于第三方签名应用允许调用；以当前版本与实际运行行为为准。

## 6. 验收与交接

按 [验收清单](acceptance.md) 逐项标记 **通过 / 未通过 / 未验证 / 不适用**，附证据来源及本轮版本。未登录欢迎页测试不能冒充实际 Cowork 任务验收。

如果仅清理登录且没有更改保护，无须为了清理重新部署网络。若为了验收启动了应用，正常退出后再清一次新缓存；说明最后留下的是已退出未登录状态。不得自动登录以证明清理成功。

交付快捷方式的实际用途、正常使用顺序、检测窗口依赖、更新后的维护方式、失败恢复方式及未覆盖范围。报告中不含密码、Cookie、OAuth 值、账户 ID 或私密订阅。
