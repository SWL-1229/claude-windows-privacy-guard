# 指定出口与失败关闭

只在用户请求配置、修复或验证保护时执行。先发现本机安装位置、专用端口和允许出口，并读取当前配置摘要；不要读取并展示私密核心配置。此公开版不附带网络网关或 WFP 安装器，需要审查现有实现或另行实施，不能仅按文档名称宣称保护已启用。

出现更新或代理连接故障时，先读 [startup-prevention.md](startup-prevention.md)。只读预检可以发现启动参数和版本不一致；通过预检仍须按下表验证出口与失败关闭。

## 先检查覆盖范围

- 用 `Get-AppxPackage` 发现 Claude 包身份、版本、安装目录；WindowsApps 常不允许普通用户枚举父目录，不用目录 glob 代替包查询。
- 检查实际目标 EXE、包 SID、WFP provider/filter、监听进程、启动项、浏览器策略；把桌面包、独立 CLI 和其他进程分开。
- 对照已注册版本。版本变化时维持离线并刷新精确规则后重测，不能因旧状态或包 SID 尚在就宣称全覆盖。
- `ERR_PROXY_CONNECTION_FAILED` 先核对实际主进程代理参数、系统代理和专用监听；不要直接认定家宽断线。Electron 单实例若复用无参数的旧进程，重开快捷方式也不能替换其代理；确认无未保存工作后完整退出，再从安全入口启动。
- 记录将修改的值与恢复方法。只有用户要求取消保护时才执行移除；修复联网不能通过删除限制、关闭防火墙或改用任意节点实现。

## 必须维持的链路性质

1. 专用链路固定入口和住宅 SOCKS5 出口，不引用共享 Clash 自动选择组，不提供 DIRECT 或其他代理回退。
2. 通过同一个专用通道检查实际公网出口，严格匹配用户允许名单。校验失败、名单无效、住宅不可达和主动锁定均拒绝新连接并撤销现有受保护转发。
3. 同时防止连接建立期间的撤销竞态。已开始的连接不能在校验失效后重新完成放行；旧缓存和旧 `status.json` 不能延长已撤销权限。
4. 原生 WFP 对目标包/EXE 只允许指定本地网关 TCP；外部 IPv4、全部 IPv6、其他本地代理端口和非 TCP 均按设计阻断。明确区分代理参数与真正的进程阻断规则。
5. 安全启动使用当前包查询与版本检查，指定 Chromium 代理和所需进程代理环境变量。持久路径避开 AppData 虚拟化；后台运行默认隐藏窗口。

专用出口探测防止意外换节点，但不是每个数据包的公网出口证明；不能把上游重新分配出口或管理员撤销规则也描述为已保证覆盖。

## 浏览器模式

受保护域名根由当前官方网络要求及本机使用情况核对，现有六根为 `claude.ai`、`claude.com`、`anthropic.com`、`claude.app`、`claudeusercontent.com`、`claudemcpcontent.com`。

- 仅精确根或 `.` 分隔的子域匹配，统一大小写和尾点；相似名称不能匹配。
- 受保护流量的 PAC 结果只有专用网关，不包含 DIRECT；PAC 强制生效且不可用时失败关闭。
- 普通站点走独立路由，跟随当前 Windows 手动代理/绕过设置。已配置代理不可用时不暗中直连；系统本来关闭手动代理时才遵循其正常直连/TUN 行为。
- 普通路由也检查目的主机，防止借普通入口绕过保护。HTTP 连接复用和 CONNECT 不能跨到未验证目标。
- QUIC/WebRTC 控制要区分“注册表写入”与“浏览器实际接受”。厂商策略支持不同，未验证时不宣称已覆盖。不要修改无关账号或安全设置。
- 改策略后完整退出并重新打开浏览器，检查实际有效策略；单独修改注册表不证明旧窗口已经生效。

## 适度验证与停止条件

使用无账号、无认证值的探测请求或隔离浏览器配置。做以下能证明此次改动的检查：

| 情形 | 预期 |
|---|---|
| 专用实际出口在名单 | 受保护请求成功 |
| 暂时主动锁定或实际出口排除 | 新请求拒绝，已有转发被关闭 |
| 住宅或网关失效 | 不借用共享代理或直连 |
| 从目标程序尝试直连、共享端口、内部核心端口 | 被对应网络规则拒绝 |
| 受保护入口锁定时访问普通站点 | 正常路由仍可使用 |
| 域名为 `notclaude.ai` 或 `claude.ai.evil.example` | 不误判为 Claude 域名 |

临时修改前记录状态，测试后恢复原值并确认未遗留锁定。测试目标程序包身份和当前版本；探测程序成功只证明其自身身份对应的测试。遇到提权拒绝、未知策略覆盖或无法确认覆盖范围，停止依赖该保证的操作并报告缺口，不重复削弱策略尝试联网。
